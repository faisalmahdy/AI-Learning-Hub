## agent

**Purpose.** A read-only monitoring, meta-communication, and evaluation layer for Faisal's personal multi-agent "fleet" — six named agents (Nusa, Manik, Patti, Malaya, Juanda, Habibie) running across three different agent harnesses (NanoClaw, OpenClaw, Hermes), with Telegram as the live comms/inference channel. The dashboard exists solely to answer "what is everything doing, and is anything wrong?" in one glance, without becoming a second job for the operator (Faisal, modeled in the system as the node "mahdy"). It is built as exactly four pieces: a canonical wire protocol every harness emits to, a reader-derived status engine (never an emitter-claimed status), a declarative agent-to-agent topology config, and an on-demand mechanical (non-LLM) behavior evaluator — explicitly not an orchestration engine, alerting system, or metrics warehouse.

**Maturity.** working-mvp, arguably polished-for-scope — evidenced by a fully fleshed 700+ line PRD walked all the way through a checkpointed build plan (CP0–CP7, all merged), 198+ passing tests across 12 test files (~2360 lines of tests), a stdlib-only import guard enforced in CI, real deployment artifacts (launchd plist, DEPLOY.md), and a documented v0-complete state in PROGRESS.md. It is small and single-purpose rather than broad, and the git history in this clone shows only one squashed commit (c8c6699), so branch/PR-level history described in PROGRESS.md is not verifiable locally — but the artifact itself (code + tests + CI config) is consistent with the narrative.

**AI concepts present.** multi-agent orchestration/observability (monitoring a fleet of autonomous coding/personal agents across heterogeneous harnesses); agent liveness / dead-man's-switch design (heartbeat-based, receive-time authoritative, never trust an emitter-asserted status); protocol-first system design for agent interop (one canonical JSON schema + discriminated envelope instead of per-harness adapters); declarative agent communication topology (who-may-talk-to-whom as versioned config data); mechanical/rule-based behavior evaluation of agents as an alternative to LLM-as-judge (explicitly rejects LLM-in-the-read-path and soft/subjective grading); fail-loud system design / anti-silent-failure patterns applied to agent monitoring (STALE/UNKNOWN/ERROR as first-class, never-green states); append-only/immutable event logging and supersede-only config versioning as trust primitives for autonomous-agent state; clock-skew and sequence-gap detection for distributed agent processes.

**Curriculum material.**

- fleet/status.py — a compact, well-commented pure function (`derive_status`) demonstrating fail-loud state derivation, clock-regression detection, and liveness-gates-phase logic; good as a worked example of defensive distributed-systems logic in ~150 lines
- schema/fleet-protocol-v1.json + fleet/protocol.py — a minimal worked example of a discriminated-union wire schema with a stdlib validator, useful for teaching schema-first protocol design

- docs/DECISIONS.md — ADR-style decision log format, useful as a template for recording engineering tradeoffs

**Gaps.** No LLM/agent code is actually invoked at runtime by this repo — it is explicitly anti-LLM-in-the-read-path; someone learning 'AI engineering' from this repo would learn agent-observability/systems design, not model usage, prompting, or RAG · Eval metrics ship mostly UNCOMPUTABLE in v0 (task_completion, task_abandon, steering_rate, repeated_miss) because the wire protocol doesn't yet carry the needed fields — the evaluation layer is more scaffold than substance right now · Kill-meter (the one metric meant to decide whether the whole tool should be kept) is itself UNCOMPUTABLE in v0 (no operator-message record on the wire) — the tool's own success criterion is unmeasured · Topology enforcement is descriptive only (v0) — the topology config records intended edges but does not actually block/allow messages between agents, so the 'access control' framing is aspirational · Single-clone git history (one squashed commit) makes it impossible to verify the PR-by-PR narrative in PROGRESS.md/DECISIONS.md from this checkout alone

## ai-engineer-learning

**Purpose.** A compounding, agent-maintained knowledge base for learning AI Engineering, built as a concrete implementation of Karpathy's "LLM Wiki" pattern (raw layer / wiki layer / schema layer kept strictly separate). On top sits an actual curriculum: T0-T3 priority tiers, a staged learning path, role-based tracks, 8 domain summaries and 13 multi-concept deep-dive modules. A second track reconstructs the AI Engineer World's Fair 2026 program as a forward map of the field, including a self-contained interactive talk explorer.

**Maturity.** polished — for what it actually is (a documentation/knowledge system, not an application): 209 schema-conformant concept pages, 131 marked reviewed against the curated corpus, a regenerable index/graph with a reported clean lint (0 errors / 0 orphans), ADR-style decision log, ingestion log, and a working interactive HTML explorer. ## business-mentor
